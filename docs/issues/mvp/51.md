## Problem

Google Stitch and the agent need the same design brief to produce comparable mockups. The owner has already selected the MVP and made visual quality mandatory. A prompt that merely asks for a mushroom map would omit several chosen interactions and might add accounts, community or offline features that belong to the roadmap.

This ticket converts the agreed product into a complete design assignment. It does not choose the winning layout or start production UI.

## Source decisions

Read `docs/product_prd.md`, especially "Main user journey", "MVP feature scope", "Language and interface quality" and "Mockup epic requirements". The agreed product is a free website with no ads or registration, all-Italy coverage, Italian and English, and today plus seven future dates. Percentages estimate porcini growing in an area and remain experimental and unvalidated.

Use `reports/Porcini app feature comparison.md` for feature examples. F14 covers background styles, visibility and opacity. It does not bring the deferred terrain, forest or soil explorers into scope. F23 is a list of private browser favorites, with names and optional colors, not an account-based journal.

[P5 phone findings](https://github.com/andreagrandi/sporameteo/blob/master/reports/p5_phone_map.md) show that date text was cramped and that readable first load did not prevent a later Safari freeze. The brief must make room for real content and usable controls.

## Proposed change

Write `docs/design/brief.md` with the product purpose, audience task, complete journey, content inventory and comparison criteria. Write `docs/design/stitch_prompt.md` as a ready-to-paste prompt that includes the same requirements without relying on this conversation or inaccessible local paths.

Both alternatives must show phone and desktop layouts for the following shared sample journey: search for an Italian place, inspect an experimental percentage for today, change to a later day, inspect weather and contributing facts, adjust the map background and overlay, save a named favorite, open external navigation and switch language. Use the same labelled design-example values in both alternatives.

The content inventory must include a whole percentage, a clear experimental notice, target date, update time, source-detail explanation, weather, recent rain for 7/14/21 completed days, favorite editing and removal, and both language labels. Describe the zoomed-out view, which shows only where forests are and invites the visitor to zoom in, the view of about 40 to 60 km across where estimates appear, squares without forest, and the required loading, first-fetch wait, no-estimate, older-update, request-error, no-search-result, denied-location and unavailable-storage states.

Specify readable typography, spacing, color use, touch controls, keyboard/focus behavior and a result explanation that does not depend on color alone. Ask for a distinct, curated visual direction rather than stock component styling. Leave the exact composition to each alternative and the final choice to #54.

## Acceptance criteria

- [ ] AC1: The brief's feature checklist covers all 16 selected IDs and names the screen or state where each is represented.
- [ ] AC2: The state inventory covers the complete journey and all listed failure/empty states on phone and desktop.
- [ ] AC3: The Stitch prompt can be pasted without extra explanation and contains the scope, example content, device expectations and requested outputs.
- [ ] AC4: A scope review finds no required accounts, subscriptions, ads, species selector, offline downloads, route planning or deferred environmental tools.
- [ ] AC5: The brief explicitly requests two alternatives and reserves the final direction for the owner's decision. It does not claim sample percentages are validated.
