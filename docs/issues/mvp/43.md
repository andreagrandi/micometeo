## Problem

The app needs a national account of forest habitat, not just the Tuscany inventory used by P2. That inventory names tree types but was surveyed in 1985 to 1993 and stops at the regional border. In the pilot, 59 inventory pasture squares now had at least 30 percent forest cover. Using that source alone would produce both missing national coverage and outdated local claims.

Copernicus forest data provides the national starting point. It distinguishes forest, broadleaf and conifer classes, but does not identify a tree species. The app must preserve that distinction in its calculations and explanations.

## Sources and reusable code

- [P2 report](https://github.com/andreagrandi/micometeo/blob/master/reports/p2_habitat.md), sections "Layers", "How each value is filled", "Forest hand check" and "Coverage and gaps".
- `src/micometeo/habitat/forest.py`, `inventory.py` and `grid.py` provide forest fractions, classification and optional regional joins.
- `tests/test_habitat.py` already covers invalid pixels, forest thresholds, no-forest cells, conflicting regional values and inventory assignment.
- [P6](https://github.com/andreagrandi/micometeo/blob/master/reports/p6_cost_licence_portability.md) records Copernicus credits and the Tuscany inventory's CC BY-SA 4.0 requirement.

## Proposed change

Attach national forest information to #41's grid using the investigated Copernicus forest-type source. Record the exact release actually used. The pilot used the 2018 release with 10 m pixels; do not describe it as a current ground survey or infer that its pixel size gives equally accurate mushroom predictions.

Reuse P2's meanings. `forest_share` is the forest fraction among valid pixels. `broadleaf_share` is the broadleaf fraction among forest pixels and is null where no forest exists. `leaf_type` uses the documented no-forest, broadleaf, conifer and mixed classes. Store valid coverage and source information separately from these values.

Process source tiles in chunks, reuse cached downloads and support restart. Regional inventory detail may enrich covered cells, but its absence must not block a national result. If the Tuscany inventory is included, retain its survey dates, disagreement indication and share-alike terms. A broadleaf class must never become "beech" or "chestnut" without a source that names it.

## Deliverables and handoff

- Repeatable forest import and joins keyed by cell ID and habitat-build version.
- National `forest_share`, `broadleaf_share`, `leaf_type`, source coverage and missing reasons, plus optional separately identified regional values.
- `reports/mvp/habitat_coverage.md` with regional counts, source dates, classifications, gaps, representative cells and required credits.
- Inputs for #47 and source facts for #50. The report states which regional additions were included rather than implying all Italy has tree-species data.

## Acceptance criteria

Add the focused checks in `tests/app/test_national_forest.py` and run
`uv run pytest tests/app/test_national_forest.py tests/test_habitat.py`.
Record the build command in `reports/mvp/habitat_coverage.md`.

- [ ] AC1: Forest fixtures verify forest and broadleaf fractions and each classification boundary using the documented P2 rules.
- [ ] AC2: Missing or unclassifiable pixels stay distinguishable from valid non-forest land. A cell with no forest has null broadleaf share, verified by a regression test.
- [ ] AC3: National coverage is reported for all regions, Sicily and Sardinia. An absent regional inventory does not remove otherwise usable Copernicus cells.
- [ ] AC4: A classification test rejects unsupported tree names. Any regional detail retains its survey date, source and disagreement status.
- [ ] AC5: Rebuild and restart checks preserve values and source versions without duplicate cells or repeated completed downloads.
- [ ] AC6: The report records redistribution and credit requirements for every included source, including CC BY-SA when regional inventory derivatives are retained.
