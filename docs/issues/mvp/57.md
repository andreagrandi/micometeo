## Problem

Visitors must be able to reach a place in Italy without already knowing how to pan to it. F13 requires place search, deliberate use of current location and selection of a map area. These actions must agree on the selected destination used later by details, favorites and navigation.

The selected map background does not automatically include permission to use a place-search service. P6 assessed tiles and weather, not a production geocoder. This ticket owns the bounded choice and configuration of a free place-search source.

## Sources and inputs

- `docs/product_prd.md`, "Main user journey" and "Map interaction", specifies all-Italy search and optional location permission.
- #56 provides map movement, cell selection and date state; #55 defines shared UI states and translation.
- [Book Corners](https://github.com/andreagrandi/book-corners) searches places in [libraries/geolocation.py](https://github.com/andreagrandi/book-corners/blob/master/libraries/geolocation.py). It calls Nominatim, the OpenStreetMap place search, through geopy, and caches answers for six hours. The public Nominatim service allows at most one request a second, requires an identifying User-Agent and attribution, and forbids search-as-you-type. Check its current usage policy before reusing it.
- [P6 map assessment](https://github.com/andreagrandi/sporameteo/blob/master/reports/p6_cost_licence_portability.md) distinguishes map-data licences from hosted service limits. Do not treat a tile provider as an unrestricted geocoder.

## Proposed change

Provide a search input and selectable Italian place results with enough context to distinguish repeated town names. Use a free source compatible with the expected requests and record its terms, attribution and limits. Prefer explicit submitted searches initially. Do not add live per-keystroke requests if the chosen provider disallows them. Cache repeat queries and respect its throttling policy.

Selecting a result moves the map to its location or bounds and lets the visitor inspect the matching area without changing the chosen forecast day. A click/tap on the map updates the shared selected point and corresponding cell. Preserve the exact selected point for navigation and favorites; an area's representative point must be identified when no more specific point was chosen.

Current location starts only after the visitor presses its control and the browser grants permission. Show a useful state for denial, timeout, unsupported location and a point outside Italy. Search and manual browsing remain available. Do not watch location continuously or store a user's location history.

Browser geolocation needs HTTPS. Ordinary HTTP on a laptop's network address does not qualify even though localhost does. Use the `tailscale serve` HTTPS address documented in #38 for the real-phone permission check, without a purchased domain or VPS. A mocked location test is useful but must not be reported as a real-phone permission result.

## Deliverables

- Search and deliberate location controls with translated states and shared selection events.
- `docs/place_search.md` covering the chosen source, request policy, caching, local configuration and secure-context testing.
- A selection contract consumed by #58, #59 and #60, distinguishing chosen coordinates from map centre.

## Acceptance criteria

Add browser checks in `tests/e2e/test_place_search.py` and run
`uv run pytest tests/e2e/test_place_search.py`. Record provider-policy and
real-device secure-context checks in `docs/place_search.md`.

- [ ] AC1: Search tests cover successful Italian results, repeated names, no result, invalid input, provider timeout and throttling, using controlled provider fixtures.
- [ ] AC2: Choosing a result preserves the forecast day and updates the map/selected point consistently. Selecting a cell by touch or mouse follows the same state contract.
- [ ] AC3: No geolocation call occurs before deliberate action. Permission-denied, timeout and unsupported-browser tests preserve search and manual browsing.
- [ ] AC4: Outside-Italy coordinates receive a clear coverage message without selecting an unrelated nearby cell or inventing an estimate.
- [ ] AC5: The documented request policy respects the chosen source's limits and attribution. Repeated searches use the cache without exposing provider credentials to the browser.
- [ ] AC6: Keyboard and phone checks exercise the result list and all error states in Italian and English.
- [ ] AC7: Local testing instructions distinguish mocked location from an actual secure-context device check and require no paid infrastructure.
