## Problem

The website needs to show real experimental percentages and let visitors compare today with the next seven days. It also needs the selected F14 controls: at least two map backgrounds, overlay visibility and opacity. P5's three pickers and synthetic map are not the chosen product UI, and its iPhone session froze after repeated movement.

Incorrect client state is as harmful as a slow map. A response for yesterday's selection must not overwrite the date or area the visitor has since chosen. Background changes must not lose the probability overlay or accumulate map instances.

## Sources and inputs

- `docs/design/decision.md` and #55's shell/state contract define presentation.
- #49 provides metadata, available dates, bounded map results and batch identity. Read its examples in `docs/api.md` before writing requests.
- [P5 report](https://github.com/andreagrandi/micometeo/blob/master/reports/p5_phone_map.md) measured a 4,000-square cap, a zoom-in prompt and a freeze on iPhone 15 Safari despite successful API calls. Its renderer's cause was not proven.
- [P6, Background map options](https://github.com/andreagrandi/micometeo/blob/master/reports/p6_cost_licence_portability.md) assessed OpenFreeMap and a local Protomaps file. OpenStreetMap's standard tile endpoint is not a default public-app provider.
- Reuse the [Book Corners](https://github.com/andreagrandi/book-corners) Leaflet integration pattern. If the assessed map source needs a different renderer, document the concrete incompatibility and device evidence rather than adding a second renderer without need.

## Proposed change

Load available batch/date metadata, then request cells for the visible area and selected target. Present eight Italian calendar dates, today through day seven. An older batch cannot supply dates it never predicted; show its real age and unavailable future dates rather than shifting its forecast forward.

Draw whole percentages using the selected design's legend and experimental notice. Missing estimates use a distinct state, not the zero-percent color. Keep map credits visible. At broad views draw #49's 10 km block summaries, labelled as the best 500 m area in each block, so the whole country shows where conditions look better. Tapping or clicking a block zooms to it instead of opening area details. Switch to 500 m squares when #49 returns them, and keep the legend clear about which of the two is on screen.

Provide two readable OpenStreetMap-based background styles from a compatible assessed source, a show/hide control and adjustable overlay opacity. Keep their choice, the selected date and selected cell stable while changing the background. No satellite or separate forest/soil layer is required.

Maintain one map instance. Debounce view changes, cancel or ignore obsolete requests and remove replaced layers and listeners. Hide or mark stale overlay content while a requested date is loading so the current label cannot describe old colors. A failed request offers a retry and identifies any retained older data. Handle a newly published batch without mixing it with the current details.

## Acceptance criteria

Add browser checks in `tests/e2e/test_map_controls.py` and run
`uv run pytest tests/e2e/test_map_controls.py` with the local application.
Record renderer measurements and sustained interaction in `docs/map_behavior.md`.

- [ ] AC1: Date-control tests show today plus seven dates in Europe/Rome and preserve actual target dates when the current batch is older.
- [ ] AC2: Map fixtures distinguish percentages, true zero, missing estimates, outside coverage and 10 km block summaries at broad views, including a view of all Italy. Tapping a block zooms to it.
- [ ] AC3: Browser tests switch between two backgrounds, hide/show the overlay and change opacity without losing date, selection or credits.
- [ ] AC4: Delayed-response tests prove an older pan/date request cannot replace the latest state. The displayed legend/date never describes a different overlay.
- [ ] AC5: Repeated background, date and viewport changes do not accumulate map instances or event handlers. Record request counts and console errors during a sustained session.
- [ ] AC6: The loading, retry, old-batch and expired-batch states work in both languages and follow the chosen phone/desktop design.
- [ ] AC7: Local performance evidence records viewport, renderer, data size and interaction behavior. The later physical-phone acceptance in #62 remains required; emulation alone cannot clear the known Safari issue.
