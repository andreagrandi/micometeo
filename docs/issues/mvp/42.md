## Problem

The national grid from #41 has geometry but no terrain. P2 already calculated altitude, slope and slope direction, but only for a small area. Extending its single in-memory 25 m raster to all Italy would create unnecessary memory use and make interruption recovery difficult.

The terrain values will feed the experimental method and area explanations. They need source and coverage information so a missing elevation tile cannot silently become zero altitude or a flat slope.

## Sources and reusable code

- [P2, How each value is filled and Reliability](https://github.com/andreagrandi/sporameteo/blob/master/reports/p2_habitat.md). The pilot uses Copernicus DEM GLO-30, a surface elevation map with about 30 m detail, reprojected to 25 m processing pixels.
- `src/sporameteo/habitat/terrain.py` contains download, slope, circular direction averaging and square summaries. `grid.py` handles raster reprojection and 500 m grouping.
- `tests/test_habitat.py` checks known tilted surfaces, flat ground, north-crossing directions and missing pixels.
- [P6 licence table](https://github.com/andreagrandi/sporameteo/blob/master/reports/p6_licences.csv) and [P2 layer inventory](https://github.com/andreagrandi/sporameteo/blob/master/data/p2_layers.csv) carry Copernicus source and attribution details.

## Proposed change

Run the terrain calculations over manageable chunks of #41's grid, downloading and reusing the required elevation tiles. Add a pixel margin around processing chunks before calculating slopes so chunk edges do not invent cliffs. The same cell must give the same result regardless of which chunk contains it.

Store `altitude_m`, `slope_deg` and `aspect_deg` with the cell and habitat-build version. Altitude and slope are area means. Direction uses a circular mean, so 359 and 1 degrees average near north rather than south. Flat or conflicting directions must remain undefined or carry the pilot's explicit low-quality indication.

Carry the P2 valid-pixel fraction and coverage rules into the stored source metadata. Explain any change to those rules. Keep factual input quality separate from confidence in the mushroom percentage. Record the source tile version, download time and real source detail. GLO-30 measures surface height and can include canopy height; resampling does not create finer evidence.

## Deliverables and handoff

- Local terrain-build command with cache reuse and resumable chunk processing.
- Stored terrain values that #47 can join by cell ID and build version without opening rasters.
- `reports/mvp/terrain_coverage.md` with per-region populated and missing counts, representative Alps/Apennines/island checks, runtime and memory, and exact attribution requirements.
- A clear distinction between existing Copernicus data, transformations applied and any missing source areas.

## Acceptance criteria

Add the focused checks in `tests/app/test_national_terrain.py` and run
`uv run pytest tests/app/test_national_terrain.py tests/test_habitat.py`.
Record the build command in `reports/mvp/terrain_coverage.md`.

- [ ] AC1: Terrain tests verify coordinate alignment and elevation in metres, then reproduce a known slope and direction, a flat surface and north-crossing directions with declared tolerances.
- [ ] AC2: A chunk-boundary test produces the same cell values whether the input is processed together or in adjacent chunks with margins.
- [ ] AC3: Missing-pixel tests preserve nulls and valid coverage fractions. They do not turn missing tiles into sea-level terrain.
- [ ] AC4: The national coverage command reports terrain coverage for all regions and explicitly lists source gaps in `terrain_coverage.md`.
- [ ] AC5: Repeating a completed chunk reuses downloads and preserves values and source references. An interrupted build resumes without duplicate rows.
- [ ] AC6: Each stored value can be traced to its source version, native detail and required Copernicus credit through the build metadata.
