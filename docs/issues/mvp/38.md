## Problem

The repository runs experiments through `uv run micometeo` and serves the P5 demonstration through a separate standard-library HTTP server. It has no Django application or persistent geographic database. Later tickets need one place to store national cells, weather batches and estimates, with repeatable local setup.

The owner chose the Book Corners stack to avoid another architecture investigation. The foundation must coexist with the research package and run without a domain, VPS or provider account.

## Sources and existing code

- Product decisions are in `docs/product_prd.md`, "Technical starting point" and "Local MVP acceptance".
- Inspect [pyproject.toml](https://github.com/andreagrandi/micometeo/blob/master/pyproject.toml), `src/micometeo/cli.py`, `.envrc.example`, which holds the GBIF login read through direnv, and the existing tests before changing package layout.

## Proposed change

Add a Django project and a Django Ninja API under a clearly documented application directory. Keep `src/micometeo` importable by both the application and experiment CLI. Add PostgreSQL with PostGIS through local Docker Compose, with a persistent local volume and a health check.

Document how to configure the application, discover its local URL and database port, run migrations and start it. Avoid conflicts with Book Corners running on the same machine. Include the native geographic libraries required by GeoDjango in the documented environment. Use local development settings and example secrets that are visibly placeholders, added to the existing `.envrc.example`.

Phones reach the laptop through Tailscale, a free private network between the owner's own devices. Document how to start the application so a phone on the same Tailscale network can open it, including the Django allowed hosts and trusted origins this needs. Use `tailscale serve` to give the local site an HTTPS address on that network, because browsers allow location access only over HTTPS and #57 needs it on a real phone. Note that Tailscale publishes the certificate name, and so the network name, in public certificate logs. Do not use Tailscale Funnel, which opens the site to the internet. The application itself must not depend on Tailscale; it is only how the owner's phones reach the laptop.

Use Italian dates for product behavior and UTC timestamps for stored events. Leave the production map and chosen visual design to #55. A minimal health endpoint is enough here. Its response must distinguish an available application from an unavailable database, without exposing configuration or credentials.

The clean-start walkthrough is recorded in `docs/local_development.md`.
