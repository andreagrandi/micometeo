## Problem

Weather must be fetched once per shared weather area and reused by every visitor and 500 m cell that depends on it. P6 estimated 1,036 counted calls per day for 392 weather cells covering only the original 28,205 square kilometre area. That estimate does not prove that downloading a full 30-day history every day for all Italy fits the free allowance.

The existing experimental client is a useful starting point, but `forecast_hourly` requests `forecast_days=1`. Its `_request` counter increments once for an entire retry sequence, `_fetch` counts quota before that sequence, and the cache key does not express every request parameter. P3 also recorded incomplete recent weather persisting in the cache. These are explicit implementation gaps for this ticket.

## Proposed change

First provide a dry-run request planner using the national grid. Record how each product cell maps to a shared weather request location and model selection. Several product cells must reuse one response. Explain the temperature-elevation policy because moving a requested coordinate can change Open-Meteo's temperature adjustment. Do not assume an invented 9 km grid represents every provider variable exactly.

Use the Forecast API for recent weather and future days. Fetch sufficient hours for today plus seven full Italian days. Bootstrap the required recent history once, retain completed days and refresh the necessary recent overlap and future forecast on later runs. Include incomplete-data refresh and expiration in the cache policy. Preserve source metadata rather than returning only anonymous hourly arrays to downstream code.

Use request identity that includes endpoint, coordinates, model choice, variables, date coverage, time-zone handling and relevant provider options. Count every network attempt, including retries. Use the existing variable/date weighting as the assessed basis, with conservative per-location accounting for multi-location requests. Cache hits consume no calls.

Persist usage across job and process restarts. Respect all four assessed limits: 600 counted calls per minute, 5,000 per hour, 10,000 per day and 300,000 per month. A dry-run over budget must prevent a download. Runtime exhaustion must defer remaining work with a reason, not silently skip Italian regions. Include initial fill, routine refresh, retries and a 31-day month in the budget.
